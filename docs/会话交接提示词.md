## 五、必须知道的陷阱（都是踩过的）

### ArkTS / ArkUI

1. **`hvigorw test` 在有用例失败时仍输出 `BUILD SUCCESSFUL`** ——
   必须同时断言 `> hvigor ERROR: Error in ` 的行数为 0。
2. **`bindSheet` / `bindMenu` / `bindPopup` 是单槽属性** —— 同一组件写两次，
   后者静默顶掉前者。多个弹层要合并成一个入口按状态分发。
3. **sheet 开关用单一 `boolean` 配 `$$` 双向绑定**，不要用「计算表达式 + onDisappear 写回」——
   会在关闭与再打开之间竞态，表现为「打开又自动关闭、且随机」。
4. **`struct` 里的 `get` 访问器不会在构建路径上求值** —— 编译通过但静默返回默认值。用普通方法。
5. **`Path.commands` 单位是 px**，`width` / `position` / `Circle` 是 vp —— 要 `vp2px()` / `px2vp()` 转换。
6. **`NavigationSystemTransitionType` / `NavigationMode` / `BarPosition` 是 ArkUI 全局枚举**，
   不要从 `@kit.UIDesignKit` 导入（会报 no exported member）。
7. **`$r()` 返回 Resource 对象** —— `$r(...) + x` 会变成 `[object Object]x`，要用 `resolveResourceString`。
8. **`List` 的 `lanes(value, gutter?)` —— 间距是第二个参数，没有 `.lanesGap()`**；属性要写在花括号之后。
9. **两列布局用 `Row { Column.layoutWeight(1); Column.layoutWeight(1) }`** ——
   `Grid` 会按行对齐留空、`WaterFlow` 在 `Scroll` 里测错行高会重叠。
10. **`@Builder` 里不能声明局部变量**；**`translate` 百分比相对组件自身尺寸**，容器宽度会变时不可靠。

### HarmonyOS 环境

11. **`command-line-tools` 不含 `sdk/default/hms/`** —— 所以 `@kit.UIDesignKit`（HDS 组件）
    在 CI 里不存在。CI 镜像必须用 `api26r`（CLT 26.0.0.821，与本机 DevEco Studio 26 Release SDK 一致），
    不能用 `api26`（Beta1，缺星闪 `manager`/`scan`）。
12. **`secrets` 上下文不能出现在 `jobs.<job_id>.if`** —— 官方可用性表只允许
    `github / needs / vars / inputs`。用了会让整个 workflow 失效，
    表现为「每次 push 产生一个 0 作业的失败运行，运行名退化成文件路径」。
    正确做法：在 step 里探测后写进 `outputs`，再用 `needs.*.outputs` 判断。

### 工作方法

13. **改文件前先全仓搜引用**（源码 + 测试 + 资源）—— 删源文件时漏查测试引用，
    曾把 `hvigorw test` 从 errors=0 变成 errors=2。
14. **按行号切片的脚本一律加 `assert`** —— 曾有脚本用 `lines[-1:-1]` 把 4118 行的主文件削成 22 行。
    每次改完先看大括号深度是否为 0。
15. **改文案/结构后要回看结构** —— 标题曾插进 `if (this.twoColumn)` 的 `else` 分支，
    两列模式下完全看不到，而编译是通过的。
16. **反复出现的缺陷类型是「同一个东西写了两遍，只改了一处」** ——
    渲染尺寸 vs 命中尺寸、竖屏标签 vs 横屏内容、详情页 vs 编辑器退出动画……
    改任何东西前先问「还有没有第二处」。
