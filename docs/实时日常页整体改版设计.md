# 实时日常页整体改版设计

> 基线：main `fcdb1d2`。先说清“实时-日常页面”指什么，避免实施时找错地方：
> 路由表明确写着日常首屏（daily）路由暂不注册（依赖 feat 的 OwnDeviceProfile 体系，已随找东西专题暂缓），
> main 里没有独立的 DailyPage。**本次改版的“实时-日常页面”就是首屏实时 Tab（日常主视角）**，
> 即 `FieldwatchPage` 内的 `FieldwatchLivePage`，以及从它直达的工具箱、安防扫描、WiFi 体检、图鉴、新面孔。
>
> 改版总方向只有一句话：**从“功能堆砌”改成“信息展示”**。每个信息块都按“结论句 → 可视化 → 入口”
> 三段式排布，没有专业知识的用户一眼看懂结论，懂行的人点数字就能进专业页。专业模式功能面不变
> （家规：不许为日常模式阉割专业模式）——日常视角是展示层重组，不是功能删减；雷达、分类、品牌筛选等
> 专业能力仍可达，只是入口从杂乱排布收进卡片里。

## 1. 通用规范：所有页面共用

- **一屏一结论**：每个卡片只讲一件事，标题就是结论句（如“当前 WiFi 正常”“发现 2 台可疑设备”），
  不用“概览”“汇总”这类空标题。
- **数字可点**：一切关键数字（设备数、可疑数、新面孔数、图鉴进度、信道拥堵度）都可点，
  点进对应的清单或详情；不可点的数字不放大展示。
- **图表一眼看懂**：图表只用三类——趋势柱状（数量随时间）、占比环/条（构成）、等级条（进度）。
  图表必须配一句话解读（如“夜间新设备明显增多”），不让用户自己猜图表含义。
- **空态给动作**：没有数据时不留空白卡片，空态文案 + 一个动作按钮（如“去扫描”“去认领”）。
- **动画三处**：弹窗出现（缩放 + 淡入）、折叠区展开/收起（高度动画）、扫描过程（雷达扫动 + 阶段指示）。
  动画只用 ArkTS / HDS 现有机制，不引入新动效库；动画时长短（200–300ms），不拖慢操作。

## 2. 实时页（日常主视角）改版

现状：实时 Tab 以雷达 + 分类行 + 品牌头 + 设备详情行为主，是专业视角的平铺，日常用户进来
不知道先看什么，也没有“今天情况怎么样”的结论。

改后信息架构（自上而下）：

| 卡片 | 内容 | 图表 / 可视化 | 卡内入口 |
|---|---|---|---|
| 今日结论卡 | 一句话结论：今日发现设备数、可疑数、新面孔数（数据来自观测与扫描历史） | 无（结论句本身就是可视化） | 点可疑数 → 安防扫描；点新面孔数 → 新面孔清单 |
| 设备趋势卡 | 近 7 日每日发现设备数 | 柱状图 + 一句话解读 | 点柱子 → 当日设备清单；入口 → 历史记录 |
| 网络状态卡 | 当前 WiFi（SSID + 频段 + 信道 + 信号）+ 一句话状态（正常 / 拥挤 / 建议换信道） | 信号强度条 | 点卡片 → WiFi 体检；入口 → 信道分析 |
| 风险与新面孔卡 | 可疑设备数、新面孔数、跟随评分（沿用三档口径，不写“安全/已排除”） | 占比条（可疑 / 正常） | 点数字 → 安防扫描 / 新面孔清单 |
| 图鉴进度卡 | 等级、积分、下一级还差多少、分类完成度 | 进度条 + 分类完成度条 | 点卡片 → 设备图鉴 |
| 工具入口区 | 常用工具一行入口：安防扫描、WiFi 体检、信道分析、反追踪、找东西 | 无 | 各入口直达对应子页面（第 3 节新路由） |

- 雷达、分类行、品牌头、设备详情等专业区块不删除，收进“专业视图”折叠区（默认收起，展开带动画），
  日常视角默认只看上面六张卡。
- 全部数字与结论的数据源必须是已有仓储（观测记录、扫描历史、房间分档、图鉴进度），不新采集、不编造。

## 3. 工具箱改版：三标签拆成三个独立子页面 + 搜索中枢

现状：`FieldwatchToolboxPage` 内用标签页切换三件现场工具（0 信道分析 / 1 反追踪 / 2 找东西），
标签与内容挤在一页，别的页面跳进来还要靠 `pendingTool` 指定第几个标签。

改后：

- **三标签 → 三个独立子页面**：信道分析子页面、反追踪子页面、找东西子页面，各自有标题与返回，
  不再共用工具箱页的标签状态；`pendingTool` 机制随分栏删除而废弃。
- **工具箱页仅保留入口 + 顶部搜索框**：页内不再放任何工具本体，只放入口列表。
  入口目录（实施时以路由表审计为准，工具型页面不得遗漏）：
  信道分析、反追踪、找东西、安防扫描、WiFi 体检、主动扫描授权（ACL 专页，附属于安防扫描条目下作二级入口）。
- **搜索框**：按入口名称与一句话说明匹配（中文子串即可），过滤后只剩命中项；
  无命中时显示空态（“没有匹配的工具，换个词试试”），不显示空白页。
- **跳转修正清单（实施时逐项 grep 核对，缺一不可）**：
  - `FieldwatchApplication.requestTab`：`toolbox` → 工具箱页；`toolbox-channel` → 信道分析子页面；
    `toolbox-antitrack` → 反追踪子页面；`toolbox-find` → 找东西子页面；`toolbox-hunt` → 寻踪页（不变）。
  - `FieldwatchPage`：`onOpenWifiAnalysis`（现为 `switchTab(4)`）→ 信道分析子页面；
    `onOpenFind`（现为 `requestTab('toolbox-find')`）→ 找东西子页面。
  - 深链：`airwavefootprints://` 下与 `toolbox-*` 相关的全部深链名同步改名。
  - WiFi 体检页信道结论卡的“去信道分析”入口（第 5 节新增）→ 信道分析子页面，**带当前频段参数**，
    进去就落在当前连接的频段上，不用用户再手动切。
  - 工具箱页自身的 TabContent（index 4）改为入口 hub；横屏 Rail 的工具箱项指向同一 hub。

## 4. 安防扫描页改版：从“按钮 + 干等 + 简陋结果”改成交互式扫描

现状问题（代码核实）：被动扫描是“点按钮 → 60 秒基线等待 → 汇总页”，扫描中只显示剩余秒数与一行文案，
用户干等；主动扫描是独立并列按钮，不是附加项；结果页是大数字 + 种类文字 + 可疑清单 + 常驻清单；
人工排查清单在 idle 页和结果页都常驻显示。

### 4.1 主动扫描改为可勾选的“附加项”

- 被动扫描是主流程，主动扫描是主流程里的一个勾选项（默认**不勾选**），放在开始按钮上方，
  文案写清它是“附加项：同时探测局域网内的联网设备（需要额外授权）”。
- **勾选时弹出带动画的提示弹窗**：弹窗出现用缩放 + 淡入动画；内容就是 ACL 授权通报四要素
  （能力 A1–A7 逐项、目标网段、暴露面、数据去向），不是笼统的“网络扫描”；
  用户点“确认”后勾选才生效，点“取消”则勾选自动回落——**勾选本身不等于授权，弹窗确认才是授权**，
  ACL 会话授权机制不变（v2 设计第 6 节），本改版只改交互形态，不改授权实质。
- 不勾选时主动入口不存在，扫描全程只有被动流程；勾选后结果页多一个“主动扫描附加结果”区
  （标注来源），与被动结论分开展示，不混算。

### 4.2 扫描过程：动画 + 阶段 + 实时计数，不让用户干等

- 扫描中界面：雷达扫动动画（复用实时页雷达动效）+ 阶段指示条（发现设备 → 分类 → 判定 → 汇总），
  当前阶段高亮，已完成阶段打勾；下方实时计数滚动更新（已发现设备数、可疑数），数字变化时有轻微脉冲动画。
- 被动扫描的 60 秒是基线观察窗：过程显示 elapsed / 剩余 + 窗内新发现数，不谎称“正在逐台探测”。
- 主动附加项勾选时，阶段条追加主动阶段（A1 枚举 → A2 端口 → A6 发现 → A3–A5 / A7 分类），
  每阶段显示当前主机数；随时可取消，取消即关全部 socket（ACL 既有行为）。
- 扫描结束自动进结果页，不用用户再点一次。

### 4.3 结果展示：学成熟软件的“风险卡片”做法

调研结论（Fing 类产品的通用做法，不是抄某一家的界面）：设备清单给人话名称与厂商、
点设备进详情（IP、厂商、开放端口、证据）；风险项用红色警示图标标出（如暴露的管理界面、弱加密）；
报告分三段：严重风险、待处理更新、行为提醒，每项配“去处理”动作；新设备加入时提醒。
落到本 App（结合三档口径，绝不写“安全/已排除”）：

- **结论卡**：一句话结论 + 三档计数（确认 / 可疑 / 未发现），不给笼统的“安全评分”。
- **风险卡片（每台可疑设备一张）**：设备名（命名回退链结果）+ 风险等级色条 + 证据分项（每项一句话人话解释，
  如“该厂商只生产摄像头”而不是 OUI 原值）+ 处置按钮（查看详情 / 忽略 / 拉黑）。
- **汇总图表**：设备类型构成条（摄像头 / 音频 / 穿戴 / 其他）+ 可疑占比条。
- **历史对比**：较上次扫描的变化（新增可疑数、新面孔数），有变化才显示，无变化显示“与上次一致”。
- **主动附加结果区**（仅勾选时）：主机数、开放端口类别、协议分类，同样用卡片式，不罗列原始报文。
- 分享卡保留；历史记录与回放入口放在结果页底部，不挤占结论区。

### 4.4 人工排查清单：默认收起，可展开/收起，带动画

- 清单不再常驻：默认收起，只显示一行标题 + 进度（“已完成 x / 11”）+ 展开箭头；
  点标题展开/收起，高度动画 200–300ms；勾选状态仍持久化（既有行为不变）。
- 展开后逐项仍可勾选，勾选即时更新标题行的进度；收起后进度仍可见，清单不“消失”。
- idle 页与结果页共用同一折叠组件，不各写一套。

## 5. WiFi 体检页改版：顶部 hero + 频段 bug 修复 + 信道分析入口

### 5.1 先回答“为什么连着 5G 却显示 2.4G 拥堵”

根因已在代码里定位，不是显示错误，是数据源写死了：

- `FieldwatchApplication.wifiSurvey24()` 写死 `surveyBand(WifiBand.BAND_24, arcs)`，即只算 2.4G。
- 体检页 `channelSummary()` 与 `recommendText()` 都调 `wifiSurvey24()`，所以信道结论卡永远是 2.4G 的
  最挤信道与推荐信道，与当前连接 AP 的频段无关。连着 DLZZ_5G 也显示 2.4G 拥堵，就是这么来的。

修复（随体检阶段落地，不单独立项）：

- 新增按频段取 survey 的接口（如 `wifiSurveyFor(band)`，复用 `surveyBand` 与现有 arcs），
  体检页信道结论卡改用**当前连接 AP 的频段**取 survey；5G 下展示 5G 拥堵，2.4G 数据不得冒充。
- 该频段无数据时显示空态（“该频段暂无扫描数据”），不得回落到其他频段的数据。
- 其他频段作次要折叠区（默认收起），点开展示对应频段结论，不与主卡抢位置。

### 5.2 顶部 hero 卡

- 体检页顶部改为一张 hero 卡，大字显示当前 WiFi SSID，下排三项：频段、信道、信号强度，
  再加一句话状态（正常 / 拥挤 / 建议换信道）；复测提醒仍置顶（P3-3 既有行为，位置不变）。
- 当前 AP 详情（SSID / BSSID / 频段 / 信道 / 信号，P3-3 已有）收进 hero 卡下方，不再单列一区；
  BSSID 随机化说明保留在详情行下（既有口径不变）。
- 底部新增入口：**去信道分析**（带当前频段参数，见第 3 节跳转清单）+ 房间趋势、复测提醒保持原位。

## 6. 设备图鉴与新面孔清单改版：从“简陋列表”改成“可看可玩的档案”

### 6.1 图鉴

现状问题（代码核实）：格子全部用同一个电波符号图标，只靠稀有度颜色区分；格子只有名称 + 稀有度；
等级、积分、进度条、分类进度、勋章、新今日数已有，但格子本身信息太少。

改后：

- **格子按类别给专属图标与配色**（摄像头 / 音频 / 穿戴 / 执法 / 无人机等已有 kind 体系，不新增分类），
  不再全格子同一图标；稀有度仍用颜色区分，两者叠加可读。
- **格子信息加两项**：首次点亮时间、该 fleet 历史出现次数；点格子进详情 sheet（设备解释 + 证据 + 跳转设备详情），
  不再只选中无下文。
- **顶部总览**：等级 + 积分 + 下一级进度条（已有）+ 分类完成度条（每类 x / y，一眼看哪类差得远）；
  增加搜索与筛选（按类别、按稀有度），611 个格子没有筛选等于没有。
- **空态与新点亮**：未点亮格子给灰态 + “去扫描发现”引导；首次点亮弹层与分享卡（P3-3 已有）保持不变。

### 6.2 新面孔清单

现状问题（代码核实）：每行只有名称（或“未命名设备”）+ 出现次数 + 特征名；有“这是我家的”移出与详情入口，
但行信息太少，用户无法判断这台新面孔值不值得处理。

改后：

- **行信息加四项**：首次出现时间、信号强度、出现趋势（今日出现次数变化）、风险提示
  （跟随评分达到关注线时标“值得留意”，不写“危险”定性）。
- **行动作加两项**：除“这是我家的”外，增加“查看详情”（进设备详情页看证据）与“拉黑”
  （进黑名单，不再出现在新面孔里）；动作放行内次级按钮，不挤占主信息。
- **分组**：按今日 / 本周分组展示，今日组置顶；空态文案 + “去安防扫描”入口。
- 对比开关（P3-2 已有）保留，位置移到列表顶部工具栏，不占行内空间。

## 7. 实施路线（分阶段，依赖关系写明）

- **阶段 1：工具箱拆分 + 搜索 + 跳转修正**（地基；后续阶段的入口目标都依赖它）。
  三标签 → 三独立子页面；工具箱页改为入口 hub + 搜索框；第 3 节跳转清单逐项落地；
  `pendingTool` 废弃；深链同步改名。
- **阶段 2：安防扫描交互与结果**（第 4 节全部：勾选附加项 + 动画弹窗 + 扫描过程动画 + 风险卡片结果 + 清单折叠）。
  ACL 授权实质不变，弹窗只是交互形态；主动结果与被动结论分开展示。
- **阶段 3：WiFi 体检**（第 5 节全部：频段 bug 修复 + 顶部 hero + 底部信道分析入口 + 其他频段折叠区）。
- **阶段 4：实时页信息架构**（第 2 节六张卡 + 专业视图折叠区；入口全部指向阶段 1–3 落地的新路由）。
- **阶段 5：图鉴与新面孔**（第 6 节全部）。
- 每阶段：hvigor test + 真机回归，**UI 改版每阶段附真机截图**（新页面与全部改动点，绕开缓存用新文件名验）；
  提交推送 main，并在文档末尾补录该阶段实施现状。

- 只对 main 提交推送；feat 分支保留为备份，绝不提交、不合入；不建新工作分支（备份用 `backup/*`）。

## 阶段 3 实施现状（WiFi 体检：频段修复 + hero + 信道分析入口）

### 5.1 频段 bug 修复（根因与修复）

**根因确认**（与设计文档 5.1 的诊断一致）：`FieldwatchApplication.wifiSurvey24()` 写死
`surveyBand(WifiBand.BAND_24, arcs)`，体检页 `channelSummary()` / `recommendText()` 都调它，
所以信道结论卡永远是 2.4G 的数据。

真机复现证据（修复前）：当前 AP `DLZZ_5G / 信道 52`，结论卡写「**2.4G** 上听到 27 个，最挤的信道是 52」
—— 数字已经是 5G 的，但文案还写着 2.4G（模板里「2.4G」是硬编码的）。

**修复**：
- 新增 `wifiSurveyFor(band)`：按频段取 survey，该频段无数据时返回 `totalAps=0` 的空结果
- 新增 `currentApBand()`：从当前连接 AP 取频段
- 新增 `wifiSurveyCurrentBand()`：体检页主卡与报告都用它
- `wifiSurvey24()` 保留为「固定看 2.4G」的显式入口（首页卡仍用）
- **空态按频段说话**：`该频段暂无扫描数据`，不回落到其他频段
- **文案模板去硬编码**：新增 `fieldwatch_wifi_band_summary`（`%1 上听到 %2 个，最挤的信道是 %3`），
  原模板 `fieldwatch_wifi_doctor_channel_summary` 里的「2.4G」是写死的，5G 下会出现「2.4G … 信道 52」这种自相矛盾的句子

修复后真机：hero 卡 `5G / 52 / -35 dBm`，结论卡「**5G** 上听到 28 个，最挤的信道是 52」。

### 5.2 顶部 hero 卡

新增一张 hero 卡：大字 SSID + 频段/信道/信号三项 + 一句话状态（建议换信道 / 信号强弱）。
当前 AP 详情（P3-3 已有）仍在其下方，BSSID 随机化说明保留。复测提醒仍在最顶部（位置不变）。

### 5.3 其他频段折叠区 + 信道分析入口

- 「其他频段」折叠区：默认收起，点开显示非当前频段的结论（无数据时明说该频段暂无数据），展开带 240ms 高度动画
- 底部新增「去信道分析」入口，**带当前频段参数**：真机验证从 5G 网络点进去，
  信道分析页的 `5 GHz` 标签已自动选中（36–161 信道），不用用户再手动切

### 阶段 3 修正的真机问题

**动态文本不能经 `@Builder` 字符串参数传**：初版 hero 卡用 `this.buildHeroCell(label, value)` 传值，
真机上三项全是 `-` —— 因为字符串参数只在首帧求值一次，`currentAp` 异步读到后不会重绘。
改为把动态值直接写在 `Text(this.heroXxx())` 节点里（符合 AGENTS.md §7.4）。
